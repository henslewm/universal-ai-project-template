## Post-merge independent review and follow-up

An independent review of merged `main` (posted through the maintainer's own GitHub account, the review that had not occurred before merge) found two real, reproducible defects. Both are answered on a follow-up branch and PR rather than reopening #9; decisions ADR-056 and ADR-057.

**P1 (ADR-056):** the printed hardware-evidence lines omitted the record's `validation_id`, so a schema-valid record made for one hardware-rung check could be appended unchanged for a different check in the same submission — level, device, firmware, observed_at, outcome, operator, dispatch_id and artifact_sha256 can all legitimately match across two checks; none of them names which check was observed. Reproduced with a room-temperature record attested against a maximum-temperature check in a two-hardware-rung contract; default status wrongly reported `VERIFIED_ON_HARDWARE`, while the record basis already refused it correctly (`record_problems` already compared the target `validation_id`). `validate_attestation` now also compares the attested `validation_id` against the attestation's own declared target, closing the attestation-basis gap the same way ADR-049 closed it for `dispatch_id`/`artifact_sha256`.

**P2 (ADR-057):** ADR-042 made the sample adapter's body read's first port contact conditional on remaining time regardless of the requested timeout, so `receive(0)` against a port with the whole frame already buffered read the header, then refused to look at the already-buffered body and raised a timeout for a complete frame that was there from the start. The body read now earns the same unconditional first contact the header always gets, exactly when the whole `receive()` call is itself a zero-timeout poll; a positive timeout keeps ADR-042's original protection (a body that arrives only after a real deadline is still refused).

**P2 follow-up (ADR-058), PR #35 review:** ADR-057's fix for a fully-buffered frame reopened the ADR-042 hazard from the other direction: nonblocking does not establish that a body was present at the initial poll, so a body that only became available strictly after `receive(0)`'s poll instant could still be returned as if received in time, while a port that hands back an already-fully-buffered frame in small chunks (no waiting involved; everything was already there) failed to be assembled, because a wall-clock deadline that starts at zero cannot distinguish either case from the other. `receive(0)` now samples `Port.available()` once, before it touches the port, as a fixed byte budget for the whole call, and never draws more than that many bytes however many non-blocking reads a trickling port takes to hand them over. `Port` gains `available()`; `SHB-04-adapter`'s contract and its pinned example hardware evidence record's `contract_hash` are updated to match.

The review's third item — the OL-016 template-packaging limitation reproduced with a fresh generation and drift count — was already recorded and explicitly not attributed to PR #34; no new action from it.
