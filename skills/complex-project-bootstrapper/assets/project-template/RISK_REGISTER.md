# Risk Register

| Risk ID | Risk | Likelihood | Impact | Early warning | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R-001 | Chat history diverges from repository state | Medium | High | Different models cite different facts | Read state files at startup; update handoff and commit | Project owner | Open |
| R-002 | Sensitive information is committed to Git | Low | Critical | Secrets or unredacted originals appear in working tree | Private repo, `.gitignore`, source index, secret review | Project owner | Open |
| R-003 | An AI performs an unauthorized external write | Low | High | Send/push/delete/permission action without clear approval | Read-only defaults and explicit approval boundary | Project owner | Open |
| R-004 | A writable local approval record is mistaken for human authentication or a security sandbox | Medium | High | Claims that the gate controls hostile code or untrusted actors | Document the workflow-integrity boundary; retain external permission controls; fail closed on missing/runtime-unverifiable state | Project owner | Known limitation |
| R-005 | Distributed skill/template copies omit the current gate | Low | High | Payload drift or generated project missing gate files | Synchronize canonical/native/standalone payloads; CI --check plus real standalone generation tests | Maintainer | Mitigated for Issue #2 |
| R-006 | Packet state, role labels or evidence strings are mistaken for verified external outcomes or execution authority | Medium | High | A recorded VERIFIED/MERGED state is cited as proof without checking real evidence | Explicit metadata-only CLI/docs; preserve revision/role/state checks; future executor enforces bootstrap and actual evidence/review controls | Maintainer | Known boundary; operational controls remain later issues |
| R-007 | Synthetic routing estimates or supplied history are mistaken for measured performance, complete usage or a hard spending limit | Medium | High | Enabling fictional models or treating replay as authentication/billing enforcement | Disable example resources; document per-role caps and estimate provenance; preserve original decision inputs; later executor/telemetry must verify live access, reserve usage and collect accepted-result observations | Maintainer | Known boundary; #4 is offline selection |
| R-008 | A local feedback record is treated as real execution, fresh dependency state or globally complete usage | Medium | High | A pending intent is executed twice, a stale graph is trusted, or a second ledger resets usage | Exclusive reservations, preserved counters and explicit trust boundary; future executor checks current graph/permissions, enforces deadlines, and reconciles all model/validator usage against the authoritative ledger | Maintainer | Local controls verified in #5; live integration remains #6/#7/#8 |
