| ADR-012 | 2026-09-13 | Refuse a dispatch whose brief, worker rules, declared harness overhead and reserved output cannot fit the context window the routed resource is actually served in, using a per-harness declared overhead and an optional per-binding served window | A live operator run failed on its first tool call because the harness system prompt alone consumed most of an 8192-token window, which the router could not see: it checks only the architect's declared tokens against the resource's declared window | Trusting the router's capacity check alone; shrinking the brief until it happened to fit; tokenizing the brief inside the harness; letting the worker discover the limit at run time | Preparation refuses with the arithmetic stated and closes the spent reservation as PROVIDER_UNAVAILABLE; the estimate is a conservative character approximation, so an understated overhead or overstated served window can still admit an impossible dispatch | Implementation decision within Issue #7 |
| ADR-009 | 2026-09-13 | Supersede the claim-release half of ADR-008: publication commits a distinct `posting` phase before any POST, a `claimed` entry is resumable because it is durable proof no POST was attempted, and an attempted publication is never retired or retried | Review showed full comment pagination proves only present absence, so retiring a claim on "no visible comment" could double-publish once an accepted comment became visible | Keeping `release` with a visibility delay; allowing an operator override flag; deleting the duplicate comment afterwards | The original stranding path is fixed without evidence-free retirement; the residual uncertain case is narrower, is documented, and deliberately has no command | Accepted within Issue #6; supersedes ADR-008 on claim release only |
