## 2. The savings goal (top priority)

- No code calls a cheaper model end to end. All tests use a synthetic harness; the Cline example config has never been exercised.
- Router calibration input is hardcoded `[]` (`scripts/feedback.py:153`). Nothing compares a frontier run to a cheaper-model run.
- **Cost-as-zero defect (confirmed by reading):** `abandon` and the preparation-failure record write `api_cost_usd: 0` (`scripts/execution_harness.py:458`, `:558-559`). That 0 is summed as real spend (`feedback.py:157`, `model_router.py:182`). A metered worker that crashes after spending money is recorded as free, so budget caps undercount and any #12 aggregate would overstate savings. Reports themselves cannot omit cost (required field), so the defect is limited to abandoned and failed attempts. Fix direction: an explicit unknown-cost state.
- Reported costs are the worker's own unverified claim (by design, `templates/harness/BOUNDED_WORKER_RULES.md:52`).
- ADR-073 plus `tests/test_worker_launcher.py:598` forbid automatic delegation. Charter item F needs a superseding ADR.
- The shipped 8192-token local-model example cannot dispatch (ADR-070); only the 16384 binding works, with 517 tokens of headroom.

## 4. Bug review of high-risk unreviewed merges

No high-impact bug was found in static review of: launcher, harness, feedback, civil-rights-nc, CLI exit/colors/progress, `sync_skills.py`, `hash_file.py`. Findings, ranked:

1. **civil-rights-nc: an own-filing source can verify a DISPUTED_FACT or INFERENCE** (`scripts/civil_rights_nc.py:238`). The ban on a filing verifying itself applies only to `fact_status == "ALLEGATION"`, so such an assertion with `source_id: SRC-X` and `verified_by: ["SRC-X"]` passes validation, and a supporting record can then earn SOURCE_VERIFIED. Reading a complaint proves only that the fact was alleged. `family_law.py:180` has the same scope, matching ADR-080's wording, so this is a design question against the charter principle that repetition never makes an allegation a fact, not an implementation slip. No test covers it. Severity: medium-high; status: reviewer was uncertain, the code path is confirmed by reading.
2. **Vacuous test:** `tests/test_civil_rights_nc.py:539` asserts `highest_level_satisfied != None`, which always holds, so the `covers_assertion is True` logic (`civil_rights_nc.py:710-713`) has no regression coverage. Should be `assertEqual(..., "structural")`.
3. **Re-verification branches untested** in civil-rights-nc: dispatch_id and artifact_sha256 mismatch (`:509-513`), validation_id and level mismatch (`:514-517`), operator mismatch (`:530`), attested-line vs record mismatch (`:533-537`), `_find_record` missing, edited or refused files (`:468-482`), and `domain_shortfall` handling (`:583-587`). Deleting any would leave the suite green.
4. **Unverified contradiction:** without `--evidence-dir`, an attestation alone can mark a claim CONTRADICTED_BY_SOURCE (`civil_rights_nc.py:610-615`, `:674-677`). Adverse direction only, but the reason text implies a source was checked when it was not.
5. **PR #70 P1, residual:** the ledger has no lock (`feedback.py:505-524`), so `abandon` or `complete` can land between the re-check (`worker_launcher.py:205`) and process start (`:214`). A millisecond window needing a concurrent operator action. Also `abandon` ignores the launch marker, so an operator can close an attempt while the worker runs and `launch` still returns `next_action: "ingest"`. Optional; needs a ledger lock, which is new scope.
6. **PR #68 P2, cosmetic:** on a rerun after attestation, progress prints `NEEDS ATTESTATION` (`scripts/acceptance.py:1058`) and a contradictory count, while the recorded gate status is correctly ATTESTED. Derive the display from `deterministic_status`. No test covers a repeated CHECKS event.
7. **`hash_file.py`:** no wrong-hash defect. An unreadable file gives a traceback and exit 1 rather than a clean refusal (minor). No direct test of the only SHA-256 evidence tool.

Not read in depth: `cli_colors.py`, `bootstrap_project.py`, `acceptance.py` beyond the cited ranges, `family_law.py`, `software_hardware.py`.

## 6. Ledger recommendation (owner decides)

Recommend GitHub issues and PRs plus the committed, hash-linked JSON ledgers as the single system of record, with the control markdown files as generated views, not hand-edited state. Add a 3-5 line settings file as the only new artifact, holding the review cap and worker-attempt default, with edits ledgered. This needs an ADR (charter D) and owner sign-off; nothing here changes a rule.
